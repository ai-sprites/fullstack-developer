# 安全与失败

沿完整请求检查信任边界：浏览器可修改所有请求字段，客户端隐藏按钮不提供授权。服务端应对真实主体、目标资源和租户范围作判断；测试换用户、换资源和缺失上下文，而不只测试未登录。

核对敏感数据在响应、URL、日志、遥测、缓存和错误提示中的去向。客户端环境变量与构建产物对使用者可见；测试账号和样例数据不应夹带真实秘密。针对当前涉及的注入、会话和跨站行为检查现有处理，不扩展成无关整改。

区分请求未发出、明确失败和结果未知。模拟慢响应、断网后重连、响应丢失或重复点击中与功能相关的情形，同时观察 UI、服务副作用和最终数据。只禁用提交按钮不能证明重试或并发不会重复执行。

缓存和异步任务可能让界面先于最终状态更新。检查失败能否被看见、数据是否保持一致、重新进入页面会看到什么，以及取消是否真的停止工作。没有证据时不要声称消息恰好一次或外部副作用可回滚。

独立部署或数据变更需要检查兼容窗口和当前授权内的恢复路径。回退应用版本与恢复数据是不同检查；没有演练的恢复步骤明确记录限制。

延伸阅读：[OWASP 授权检查说明](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。只用来核对受影响边界，不把它变成整个项目的新增审批清单。
