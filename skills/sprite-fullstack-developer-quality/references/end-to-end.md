# 完整路径检查

先确认被测前端、后端与资料依据分别是什么版本。单端测试可以隔离问题，但两边各自通过不证明真实通信成功；至少对当前关键用户结果在合适环境验证实际接口、身份与持久化行为。

按风险使用测试层次：纯逻辑检查边界值，服务检查业务结果与状态，契约检查请求响应语义，完整路径检查操作后用户是否看到应有结果。不要把所有逻辑堆进慢而脆的端到端测试，也不要只检查元素出现就断言功能完成。

契约改变要保留有意义的新旧消费者组合。检查可空性、默认值、枚举、错误、排序和缓存；类型编译通过无法证明运行数据一致。部分环境不可用时明确缺少的组合，不用模拟结果冒充已联调。

对界面变化做相关视口、键盘、焦点、标签和实际状态检查；对数据变化核对持久化、事务以及旧行为。视觉和无障碍检查分别说明方法，不以截图正常替代可操作性。

回归选择本次调用链与共享组件受影响的邻近路径，使用合成数据并清理测试引入的副作用。先确认清理范围，避免删除环境中其他人的资料。

报告以验收项或用户行为为线索，链接真实输出。未运行、环境阻碍、产品缺陷和原有故障分开；重复重跑不应取代偶发问题调查，不能把降低断言当成修复。

延伸阅读：[Testing Library 指导原则](https://testing-library.com/docs/guiding-principles/)，用于行为观察的思路，无需据此更换测试框架。
